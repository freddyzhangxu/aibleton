# 可折叠任务执行回执设计

## 目标

将任务执行回执默认收起为与工具调用摘要相同高度的一行，减少聊天记录中的视觉占用；用户点击该行后可查看完整、已持久化的回执内容。

## 行为

- 每个已有回执默认收起，包括历史会话中的回执。
- 收起时只显示本地化标题与状态：`任务回执 · 已执行`、`任务回执 · 已达标`、`任务回执 · 未达标`，或对应界面语言的翻译。
- 收起行使用与 `.steps summary` 相同的高度、内边距、三角箭头和点击区域。
- 点击标题行展开/收起；展开时展示目标、实际改动、系统校验、试听建议和 Undo 提示。
- 状态继续由左侧边框和文字色辅助表达；关键状态始终有文本，不只依赖颜色。
- 纯读取、失败或拒绝操作仍不生成回执。

## 实现

- 将回执外层从 `section` 改为原生 `details.receipt`。
- 用 `summary` 承载折叠标题与三角箭头；内容放在一个 `.receipt-body` 容器中。
- 复用 `.steps` 的交互模式而不新建 JavaScript 状态、事件监听或持久化字段。
- 调整 CSS，使收起摘要与 `.steps summary` 同为单行、`3px 8px` 内边距，并在打开时显示正文分隔线。
- 现有 `receipt` 数据模型、服务端构建器和历史 API 不变。

## 错误处理与验收

- 缺少或畸形 `receipt` 保持不渲染。
- 不受支持的 status 继续回退为 `completed`。
- 浏览器回归验证：默认收起、标题本地化、点击后完整展开、再次点击收起、窄窗口无横向溢出，以及无 receipt 的只读消息不出现回执。
- 全套单元测试、UI 脚本解析和生产构建必须通过。
